## 0. 最初にやること（いま残っている作業）

**exe を作る。** これが唯一の未完了タスクです。

```powershell
# Windows 側（WSL ではない）で
cd <このリポジトリ>
python -m pip install -r requirements.txt
build\配布物を作る.bat
```

**Linux では作れません。** クラウドだからではなく、**PyInstaller はクロスコンパイル
できない**ためです。Windows の exe は Windows 上でしか作れません。

想定される躓き:

| 症状 | 対処 |
|---|---|
| `pip` が認識されない | `python -m pip` を使う（スクリプトは全てこの形に統一済み） |
| exe が数百 MB になる／ビルドが落ちる | miniconda 環境が原因のことが多い。python.org 版の Python 3.11+ に切り替える |
| セキュリティソフトに止められる | 未署名 exe のため。オフライン端末での実測が必要（下記「未検証」参照） |

ビルド方式は **PyInstaller `--onedir`**（`--onefile` は起動が遅く、DVD 配布に不向き）。

## 1. この道具は何か（一言で）

> **今年度のスキャンデータを 2 名 1 組で見直し、来年に向けた「論点」と「教材」を作る道具。**

**実際の審査を自動化する道具ではありません。** ここを取り違えると設計判断を誤ります。

### 背景

指定難病受給者証の一斉更新の書類審査で、担当者ごとに OK/NG の判断がブレる。

| 項目 | 数字 |
|---|---|
| 申請件数 | 約 1 万件／シーズン |
| 不備率 | 約 15%（約 1,500 件） |
| **解釈が分かれる（管理者確認が要る）もの** | **全体の 3〜4 割＝3,000〜4,000 件** ← **これを減らすのが目標** |
| オペレーター | 繁忙期のみ雇用、**毎回入れ替わる**（経験が組織に残らない） |
| ピーク | 5 月勧奨通知 → 6 月初旬返送 → **6 月中旬〜7 月 15 日頃**、約 4 名で一次・二次 |
| 見直し作業の体制 | **2 名 1 組**、1 申請 1 回。閑散期（〜2027 年 2 月頃） |
| 契約 | 3 か年の最終年（**来年が最後**） |
| 見直し対象 | **全 1 万件**（不備かどうかはファイル名から分からないので絞れない） |
| 工数見積 | OK 約 6,500 件×30 秒＝54h ＋ NG 約 3,500 件×5 分＝292h ＝ **約 346 時間** |

### ブレの真因（コンサルティングでの再定義）

「判断基準が無い」のではない。管理者は一貫して判断しており、**明文化されていない**だけ。
真因は 4 つ:

1. **書類の同定ができない** — 資格確認書／資格情報のお知らせ／マイナポータル PDF は OK、
   旧保険証／高齢受給者証／保険者作成の医療費一覧は NG。**見分けがつかない**
2. **同じ書類の提出形態が多様** — 自己負担上限額管理票が複数ページ、申請者が月ごとに切り貼り
3. **複数書類の突合** — 中間サーバー照会結果と申請書と資格確認書の 3 者整合など
4. **答えが決まっていない論点** — 記号番号は一致するが**枝番のみ相違**、など

共通原理として抽出した問い:
> **「その書類は、確認したい情報そのものの証明になっているか？」**（管理者の確認待ち）

### クリティカルパス

**管理者による未決定論点の回答（2026/12〜2027/2）。** 全件終わってから相談を始めると
間に合わないため、事前バッチ（メモ欄の黒画素率）で書き込みのある案件を先に回す設計にしてある。

## 2. 絶対に守る制約

ユーザーが明示した制約。**これを崩す提案をしないこと。**

- **スキャンデータそのものは外部持ち出し一切不可**（機微な個人情報を大量に含む）
- **実行環境は完全オフライン**（インターネット接続不可）。ツールの持ち込みは可
- **Python 導入不可。パッケージ済み exe は実行可**（試作 exe で実証済み）
- **配布は DVD**
- **マスキング済みなら持ち出し・印刷可**（センター内で承認済み）
  - ※途中で「センター内だけなのでマスキング不要では」と判断を誤り、**2 度撤回した**。
    マスキングは**オフライン端末から取り出して印刷するときに必要**

これらの帰結として:

- **依存ライブラリを増やさない**（wheel 同梱と exe 肥大化のコストが直に効く）
- **判定表は exe に埋め込まず外部 CSV**（Excel で改訂でき、契約終了後も資産として残る）
- **判断ロジックは GUI から分離**（tkinter 無しで検証できる＝実データ無しで担保できる）

### ファイル名規則（`caselist.py`）

```
25A1234567A001_20260615_1
^^ ^^^^^^^ ^^^  ^^^^^^^^ ^
prefix 受給者番号 枝番   日付   通し番号
```

- **通し番号が奇数なら申請書一式、偶数なら臨床調査個人票**
- 重複した受給者番号は**日付の古いものを本体**、残りを追加書類
- `swap_primary()` で画面から入れ替え可（先に不備書類だけ届くことがあるため）

### 判定表 CSV（`data/`）

| ファイル | 内容 |
|---|---|
| `チェックリスト設問.csv` | 設問 ID・大項目 N・確認書類・枝番 #・設問文・**前提設問 ID**・**ツール対象**・表示順 |
| `不備理由.csv` | 未提出／不一致／無効書類／書類不足／確認不可 |
| `判定_単独.csv` | 設問 ID・書類 ID・区分（有効/無効/要相談）・不備理由・理由・記入方法・決定状況・決定者・決定日 |
| `判定_組合せ.csv` / `判定_突合.csv` | `*` ワイルドカード、`対象書類` 列 |
| `書類種別.csv` | **仮登録**列あり |

書2-*（臨個票）と書4d-*（追加提出分）は `ツール対象=×`。**入力対象は 17 問 → 12 問。**

依存関係:
```
書3-1（医療保険資料が提出されている）→ NG なら 書3-2 / 書3-3 は判定不能
書4-1（管理票が提出されている）      → NG なら 書4-2 / 書4-3 は判定不能
```

**突合は基準書類方式**（全列挙しない）。3 点＝5、4 点＝15、5 点＝52 通りで爆発するため。

## 4. 過去に踏んだ地雷（**再発させないこと**）

修正済みだが、リファクタで壊しやすいものを挙げる。

### 【重大】署名はページ全体から取ってはいけない（`detect.py`）

ページ全体から署名を取ると、**メモ欄の手書きが署名を支配し、書き込みの多いページほど
検出できなくなる**。書き込み 9 行で類似度 0.223 まで落ち、無関係なページの 0.404 を
下回った。**一番拾いたい対象を落とす致命的欠陥。**

```python
FORM_REGION = (0.0, 0.03, 1.0, 0.82)   # 上部 82% に限定
DEFAULT_THRESHOLD = 0.70
```
修正後は記入あり 0.911 以上／無関係 0.247 に分離。

### 【重大】「未入力」と「未提出」は違う（`session.py`）

書類を 1 つも選んでいない状態で 書3-1 が自動的に NG（未提出）になっていた。
**案件を開いた瞬間に不備が決まったように見える。**

```python
if not self.documents:
    return None      # 書類を 1 つも選んでいないうちは判定しない
```

### `PageCache` が渡したインスタンスを捨てる

`self.cache = cache or PageCache()` は、`__len__` を定義した空のキャッシュが偽と
評価されるため常に新規作成される。`cache if cache is not None else PageCache()` が正。

※ 当初これを PyMuPDF のスレッド安全性の問題と**誤診断した**。`_PDF_LOCK` は
「PyMuPDF は公式にスレッドセーフではない」という別の根拠で残してある。

### Tk のラジオボタンが未入力時に全選択済みに見える

`tristatevalue` の指定が要る。**`"\x00"` は Tcl 側で空文字と同じ扱いになり無効。**
実在しない文字列を使う: `NEVER_SELECTED = "未選択"`

### その他

| 問題 | 対処 |
|---|---|
| 作業窓でページが表示されない | Tk が寸法を決める前に倍率を計算していた。`update_idletasks()` ＋ `user_adjusted` ＋ リサイズ再フィット |
| 関係ない書類まで判定に渡していた | `RuleSet.relevant_docs()` で設問ごとに絞る |
| 「すべて OK」が判定表の答えを塗り潰す | **判定表が答えを持たない設問だけ** OK にする |
| 8 色中 7 色で罫線が薄すぎた（2.1〜2.7:1） | 全色 3.0:1 以上に。**目視では気づけない。テストが検出した** |
| Esc が実質取り消せない操作だった | `session.clear()` を**1 回の操作**にし（Ctrl+Z 一度で戻る）、確認ダイアログを追加 |
| `pip` が認識されない（ユーザー実機） | `python -m pip` / `python -m PyInstaller` に統一 |

### 逐次保存

`autosave: bool = True`。`set_documents` / `set_check` / `all_ok` / `undo` / `clear` の
各操作後に `save()`。**「状態を保存して閉じる」だけでは編集中の 1 件が失われる**という
指摘を受けての変更（停電対策も兼ねる）。

## 5. UI について（最後に実装した内容）

**ライブラリを追加せずにフラット化した。** ttkbootstrap / CustomTkinter は**不採用**。
再提案しないこと。理由:

- 素の tk が **126**、ttk が **11**。**装飾対象の 9 割が ttk ではない**
- CustomTkinter には **Listbox 相当が無く作業リストが作れない**。
  `tk.Canvas` のマークアップも包めない
- オフライン配布で依存を増やせない。検証済み配色 8 色を失う

### 実装方式：「組んだ後に磨く」

```python
# ui.py
SKIP_ATTR = "_shinsa_no_polish"
def polish(widget, theme) -> None:
    """組み上がった画面を平らにする。子まで再帰する。
    構築側のコードに触らないので、bind も grid/pack も影響を受けない。"""
```

**構築側に一切触れないため、キーボードのイベントと配置がコードの構造上壊れない。**
Button/Entry/Listbox/Checkbutton/Radiobutton/Text/Scrollbar/Menu を平坦化。
**Label/Frame/Canvas は触らない**（Canvas はマークアップ描画に関わる）。
`setup_ttk_style()` は ttk を `clam` にしてテーマ色で塗り直す。

### 配色の基準

**WCAG コントラスト比：本文 4.5:1、枠線 3.0:1。** `tests/test_theme.py` が 96 組を検証。

| 色 | 白地とのコントラスト | 扱い |
|---|---|---|
| `#475569` | 7.58:1 | 補足文字に採用 |
| `#3B82F6` | 3.68:1 | **枠線・強調のみ。文字には使わない** |
| `#EF4444` | 3.76:1 | **枠線・強調のみ** |
| `#D1D5DB` | **1.47:1** | **使わない。**罫線に使うと行が追えなくなる |

8 テーマ: 標準／アイボリー／ミント／サクラ／スカイ／ラベンダー／高コントラスト／ダーク。

## 8. ユーザーとのやり取りで学んだこと

方針転換を伴った指摘。**同じ誤りを繰り返さないために残す。**

- 「多すぎて列挙できない」「思い出せない」
  → **記憶ベースの棚卸しは成立しない。現物データからの機械的収集へ**
- 「何が不備になったかをファイル名から機械的に持ってこれないから、結局全部見る必要があるよ」
  → **サンプリング方針は誤り。全件方針**
- 「マスキングは必要。オフライン端末から取り出して印刷するときに必要」
  → **こちらの「不要」判断が誤り。2 度撤回した**
- 「これとこれとこれがあって…を選択したら『こうしてください』が出るものを作りたい」（3 回表明）
  → **当初の否定的評価を条件付きで撤回した。ユーザーは同じ要望を繰り返している**
- 「追加提出分って基本使わないよね？」→ 書4d-* を対象外に（12 問へ）
- 「状態を保存して閉じる機能ってあるよね？」→ **穴の発見。逐次保存へ**

**このユーザーは業務を正確に把握している。** 実務の事実（件数・体制・様式）については
ユーザーの記述を一次情報として扱い、こちらの推測で上書きしないこと。
一方で、**技術的な提案の是非は数値で判断する**ことを求められている（コントラスト比、
ウィジェット数、工数など、根拠を数字で示すこと）。

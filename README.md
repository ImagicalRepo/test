# 指定難病 一斉更新 書類審査 支援ツール

指定難病受給者証の一斉更新において、書類審査の判断ブレを減らすための道具一式。

**いま作っているのは「今年度データの見直しツール」です。** 実際の審査には使いません。
今年度のスキャンデータを 2 名 1 組で見直し、**来年に向けた論点と教材を作る**ためのものです。

| 項目 | 内容 |
|---|---|
| 申請件数 | 約 1 万件／シーズン（ピークは 6 月中旬〜7 月 15 日頃） |
| 解釈が分かれるもの | 全体の 3〜4 割（3,000〜4,000 件）← ここを減らすのが目標 |
| オペレーター | 繁忙期のみの雇用で**毎回入れ替わる**（＝経験が組織に残らない） |
| 見直しの体制 | **2 名 1 組**。閑散期に全 1 万件を見る（約 346 時間の見込み） |
| 実行環境 | Windows・完全オフライン・Python 導入不可（exe は実行可）・配布は DVD |

## 2 つの exe

### 審査データ見直しツール（2 名 1 組・閑散期）

```
python tool_review.py
```

フォルダを取り込むと作業リストができ、1 件ずつ開いて審査を再現する。

- **何が届いているか**を選択式で入力（手入力不可）。ブレの主因を入口で縛る
- **チェックリスト 14 問**。大半は「すべて OK」1 クリックで終わる
- 前提が NG の設問は自動で**判定不能**になり、入力を求めない
- NG・迷いは**作業窓**で左右に並べて見比べ、**2 箇所を囲むと線で結ばれる**
- マスキングは**未／済／不要**で管理。「未」が残っていると持ち出せない
- ツールメニューに **事前バッチ**（確認順序の決定）と **出力点検**

### 書類審査 判断支援ツール（来年のピーク・紙の横で）

```
python tool_b.py
```

提出書類を選ぶと **OK / NG / 管理者に相談** と理由、チェックリストへの記入方法を表示する。

## 判定内容は CSV にある（exe に埋め込まない）

```
data/
  書類種別.csv            画面に出す書類の選択肢（仮登録の印を含む）
  チェックリスト設問.csv   設問・前提設問ID・ツール対象
  不備理由.csv            未提出／不一致／無効書類／書類不足／確認不可
  判定_単独.csv           どの書類が有効／無効か
  判定_組合せ.csv         特定の組み合わせの例外
  判定_突合.csv           複数書類の突合
```

**Excel で直せば判定が変わる。exe の作り直しは不要。**
可読形式で残るので、契約終了後もそのまま引き継げる。

> 保存時は必ず「**CSV UTF-8（コンマ区切り）**」を選ぶこと。

**判定表に無い組み合わせは、必ず「管理者に相談」を返す。** 黙って OK を出すことはしない。

## 現在の状態

判定表には、ヒアリングで確認できた範囲だけが入っている。
**多くは「たたき台」または「未決定」**で、管理者の決定を待っている。

最優先は **「記号番号は一致しているが枝番のみ相違する場合の扱い」**（毎年ブレている論点）。
→ [`templates/未決定論点リスト.csv`](templates/未決定論点リスト.csv)

## 構成

```
src/shinsa/
  caselist.py   フォルダ走査・ファイル名解析・重複解決（最古を本体）
  store.py      SQLite で作業状態を永続化（中断と再開）
  session.py    1 件の判断ロジック（画面なしで検証可能）
  rules.py      判定エンジン（単独・組合せ・突合・依存関係）
  markup.py     比較マークアップ（左右 2 領域＋結線＋書類名ラベル）
  masking.py    マスキングと安全な書き出し
  viewport.py   表示領域の座標計算（画面 ⇄ ページ比率）
  prefetch.py   ページの先読み（OK 案件 30 秒の要）
  prescan.py    メモ欄の黒画素率で確認順序を決める
  detect.py     チェックリストのページ検出
  pdfio.py      PDF のページ画像化
  app_review.py / app_canvas.py / app_tools.py / app_b.py   画面
  config.py / ui.py
```

**判断は画面から切り離してある**（`session.py` / `rules.py`）ので、
tkinter なしで検証できる。

# 業務スケジュール管理ツール（指定難病 医療費助成ほか）

「審査会が◯日、その20営業日前が受付締切、決裁は起案からN営業日後、その翌々日が封入封緘、その翌日が発送……」
という**基準日から前後へ多段に伸びるスケジュール**を、Googleスプレッドシート・ガント画面・Google Chat 通知で管理します。
指定難病の月次審査会、一斉更新、小児慢性特定疾病など、**周期の違う複数の業務を並べて見る**ことを想定しています。

## 特徴

- **基準日を1つ直せば、ぶら下がる全工程が自動で計算し直される**（審査会が1週間ずれても手直し不要）
- 工程は「基準日から」だけでなく「**前の工程から**」も定義できる（決裁完了＝起案の3営業日後、など）
- **土日・祝日・年末年始の閉庁日を自動で飛ばす**（祝日は内閣府の公開CSVから取得）
- **3つのビュー**で見られる ── 業務横断ガント／業務別の流れ／月間カレンダー
- **カラーテーマ8種**（パステル系4種を含む）とダーク。動きは控えめなアニメーションで補助
- 毎朝、**Google Chat に「期限超過／本日／まもなく」**を自動投稿
- **個人情報を持たない設計**。工程名と日付だけを扱う

## 個人情報について

このツールは**受給者の氏名・疾病名などを一切保持しません**。「11/12 封入封緘」といった工程と日付だけを管理します。
そのため、個人情報保護条例やクラウド利用の内規に関する説明がしやすくなります。
案件単位の進捗管理が必要になった場合は、必ず所属団体の規程を確認してください。

## 必要な権限

**特別なライセンスや申請は不要**です。Googleアカウント（Workspace / 個人）があればそのまま使えます。
初回実行時に、次のスコープをあなた自身が承認します。

| スコープ | 用途 |
|---|---|
| `spreadsheets` | シートの読み書き |
| `script.external_request` | Google Chat への通知、祝日CSVの取得 |
| `script.scriptapp` | 毎日の自動実行トリガー |
| `script.container.ui` | メニュー・画面の表示 |

**カレンダー権限とGmail送信権限は既定では要求しません。**（カレンダー連携は後述の手順で任意に有効化できます）

### 「このアプリはGoogleで確認されていません」と出たら

自分が所有者の自作スクリプトなので問題ありません。［詳細］→［(プロジェクト名)に移動］で進めます。
外部公開しない限り、OAuthの審査は不要です。

### 動かない場合に疑うところ

1. **組織の管理者設定** — 管理コンソールで Apps Script 自体が無効化されていることがあります。
   まず捨てシートで `Logger.log('test')` を1回実行し、承認画面が出るか確認してください。
2. **ネットワーク** — LGWAN接続系の端末からは Google に接続できません。インターネット接続系で使ってください。
3. **トリガーの実行者** — 定時トリガーは**設置した人のアカウント**で動きます。
   異動・アカウント停止で通知が止まるので、引き継ぐときは後任が［通知トリガーを再設定］を実行してください。

## 導入手順

**インストールするものはありません。** ブラウザとGoogleアカウントだけで、15分ほどで終わります。

> 詳しい手順は **[docs/導入手順.md](docs/導入手順.md)** にあります。承認画面の進み方や
> つまずいたときの対処もそちらにまとめてあります。

おおまかな流れは次のとおりです。

1. スプレッドシートを新規作成し、タイムゾーンが「東京」か確認する
2. ［拡張機能］→［Apps Script］を開く
3. **`dist/` の5ファイルを貼り付ける**（`コード.gs` / `gantt.html` / `editor.html` / `json.html` / `appsscript.json`）
   - `dist/コード.gs` は全スクリプトを1つにまとめたものです。コピーの手間を減らすために用意しています
   - HTMLファイルの名前は `gantt` `editor` `json` にしてください（コードから名前で呼んでいます）
4. スプレッドシートを再読み込み → メニューに **📅 業務スケジュール** が現れる
5. ［**初期セットアップ**］を実行し、権限を承認する
6. ［設定］シートの **ChatWebhookURL** を埋める（次項）
7. ［**Chatにテスト通知**］で疎通を確認する

`clasp` を使う場合は `apps-script/` をそのまま `clasp push` できます。
`dist/` は `npm run bundle` で作り直せます。

### Google Chat の Webhook URL の作り方

通知したい Chat のスペースを開く → スペース名をクリック → ［アプリと連携］→ ［Webhook を追加］→
名前を付けて作成 → 表示された URL をコピー → ［設定］シートの `ChatWebhookURL` に貼り付け。

## 使い方

### 日々の運用

| やりたいこと | 操作 |
|---|---|
| 全体を見る | メニュー →［スケジュール画面を開く］ |
| 工程を完了にする | 画面上の工程をクリック →［完了］／ 工程表シートの「完」にチェック |
| 審査会の日を変える | 画面上の基準日リンクをクリックして入力（全工程が再計算されます） |
| 工程の内容を変える | メニュー →［工程テンプレートを編集］ |
| 通知を今すぐ試す | メニュー →［Chatにテスト通知］ |
| サンプルを消して自分の業務にする | メニュー →［サンプルを削除して最初から作る］ |
| 画面の大きさを変える | ［設定］シートの `画面の幅` `画面の高さ` を変更（下記） |
| スケジュール画面だけを別ウィンドウで使う | メニュー →［別ウィンドウで開く（URLを表示）］（下記） |
| その URL が開けない | メニュー →［WebアプリのURLを登録］に、実際に開ける URL を貼り付ける（下記） |

毎日 1時に工程表が自動更新され、設定した時刻（既定8時）に Chat へ投稿されます。

### 3つのビュー

画面上部のタブで切り替えます。左側の「期限超過／本日／まもなく」はどのビューでも出ています。

| ビュー | 見えるもの |
|---|---|
| **ガント** | 全業務を横断した時間軸。回次ごとに1レーンで、工程の丸と基準日の◆が並ぶ。**業務どうしの山場の重なり**が一目で分かる。凡例のチップで業務を絞り込み、小/中/大で日付の幅を変えられる |
| **業務別** | 1つの業務を選んで、回次ごとにカード表示。工程が縦のタイムラインで並び、**進捗バー**と各工程の残営業日が出る。「この業務がどう流れるか」を追うとき用 |
| **月間** | 通常のカレンダー形式。複数業務の工程が**業務色のチップで混ざって**日付に乗る。「今月は何がどう重なるのか」を見るとき用。1日に4件以上あるときは［＋N件］で展開 |

### 画面の大きさ

Apps Script のダイアログは、仕様上あとからドラッグでリサイズできません。
代わりに［設定］シートで指定します。

| 設定キー | 既定値 | 備考 |
|---|---|---|
| `画面の幅` | 1400 | ブラウザの幅より大きくはなりません |
| `画面の高さ` | 800 | 画面の小さいPCでは 640 程度に下げてください |

月間カレンダーは与えられた高さに合わせて自動で詰まるので、低い画面でも1か月ぶんが収まります。

### 別ウィンドウで使う（ウェブアプリ）

**自由にリサイズしたい／スプレッドシートを開かずに使いたい場合はこちらです。**
ウェブアプリとして公開すると、ブラウザのタブで各画面を単独で開けます。

1. ［拡張機能］→［Apps Script］→ 右上の［デプロイ］→［新しいデプロイ］
2. 歯車マーク →［ウェブアプリ］
3. 次のユーザーとして実行：**自分** ／ アクセスできるユーザー：**自分のみ**
4. ［デプロイ］→ 承認 → 表示された URL をブックマーク

**2つの画面がURLで切り替わります。**

| 画面 | URL |
|---|---|
| スケジュール（ガント／業務別／月間） | `.../exec` |
| 工程テンプレートの編集 | `.../exec?page=editor` |

ウェブアプリで開いているときは、画面の右上に相互のリンク（［工程を編集 ↗］／
［スケジュールを見る ↗］）が出ます。ダイアログで開いているときは出ません。

以後は、メニュー →［別ウィンドウで開く（URLを表示）］で両方の URL を確認できます。

#### URL が開けないとき

末尾が `/exec` の URL は、**デプロイした時点のコードを動かします**。
コードを貼り替えても再デプロイしていないと古いままで、`doGet` が無かった頃のバージョンを
指していると開けません。次のどちらかで直ります。

**A. 再デプロイする（URL は変わりません）**
［デプロイ］→［デプロイを管理］→ 鉛筆マーク → バージョンを「**新しいバージョン**」→［デプロイ］

**B. 開ける URL を登録する**
［デプロイ］→［**デプロイをテスト**］に出る末尾 `/dev` の URL は、常に最新のコードで動きます
（自分だけが開けます）。その URL をコピーして、メニュー →［**WebアプリのURLを登録**］に貼り付けると、
以後［別ウィンドウで開く］と画面右上のリンクがその URL を使います。
`?page=editor` が付いたまま貼り付けても、自動で外して登録します。

登録内容は［設定］シートの `WebアプリURL` に入ります。空にすればデプロイの URL に戻ります。

### サンプルを消して自分の業務を登録する

メニュー →［**サンプルを削除して最初から作る**］で、業務マスタ・工程テンプレート・基準日・工程表の
4シートを空にします。**設定と休日マスタは残る**ので、手入力した閉庁日は失われません。

削除後は工程テンプレート編集画面が開くので、［＋ 業務を追加］から
業務ID・業務名・基準日の呼び方・周期を順に入力して登録します。

### 印刷

各画面のヘッダーにある［**印刷**］から、A4横で刷れます。
「今日やること」の欄と操作ボタンは紙には出ません。

| ビュー | 紙に出るもの |
|---|---|
| ガント | 各工程を**吹き出しで名前と日付を出した状態**。日付が近い工程は段を分けて重ならないように配置されます |
| 業務別 | 回次ごとのカード。回次の途中でページが割れないようにしています |
| 月間 | カレンダーそのまま |

ガントは用紙の幅に収まるよう、1日あたりの幅を自動で詰めます。
横に長すぎる場合は［設定］シートの `先読み月数` を減らすと見やすくなります。

### カラーテーマ

右上の［🎨 テーマ］から8種類。選択はブラウザに保存され、工程テンプレート編集画面にも反映されます。

| テーマ | 系統 |
|---|---|
| ペーパー | 標準（白＋青） |
| さくら / ミント / ラベンダー / サンド | パステル系 |
| オーシャン / スレート | 落ち着いた寒色系 |
| ナイト | ダークモード |

業務マスタの「色」は**色名だけ**を持ち、実際の色はテーマ側で決まります。テーマを変えても業務ごとの色分けは保たれます。

アニメーションは、OS側で「視差効果を減らす」を有効にしている場合は自動的に無効になります。

### 工程の定義のしかた

［工程テンプレートを編集］の画面で、各工程を次の形で定義します。**右側に実日付が即時プレビュー**されます。

**業務名・工程名・基準日の呼び方は、すべて自由に決められます。**
最初に入っている3業務はサンプルなので、消して自分の業務に置き換えて構いません。
［＋業務を追加］で新しい業務（例：予防接種、療育手帳、精神保健福祉手帳など）をいくつでも足せます。

各工程は**一文**として並びます。日付の決め方は3通りあり、行の先頭で選びます。

```
　封入封緘・点検                                    9/18(金)
　〔起点から ▾〕〔受給者証・通知書の印刷 ▾〕の〔1〕〔営業日 ▾〕〔後 ▾〕

　年1回の全件点検                                   9/14(月)
　〔日付指定 ▾〕〔2026-09-14〕

　窓口受付期間                              8/12(水)〜8/26(水)
　〔起点から ▾〕〔審査会 ▾〕の〔20〕〔営業日 ▾〕〔前 ▾〕から〔10〕〔前 ▾〕まで
```

| 決め方 | 使いどころ |
|---|---|
| **起点から** | 「審査会の20営業日前」。起点が動けば自動で追随します |
| **日付指定** | 起点と関係なく「この作業はこの日にやる」が決まっているとき |
| **期間** | 「この日からこの日までやる」。どちらの決め方でも［期間にする］で切り替え |

工程を追加したときの既定は［**日付指定**］で、日付にはその日が入っています。
起点からの相対で決めたい工程だけ［起点から］に切り替えてください。
シートに直接行を書き足したときも、`日付種別` が空で `開始日` だけ入っていれば日付指定として扱います。

右端に出るのが、その設定で**実際に何日になるか**です。設定を変えるとその場で変わります。
期間の工程は `8/12(水)〜8/26(水)` のように両端が出ます。
起点と同じ日になる工程は緑、計算結果が休日になる工程は⚠付きの黄色で表示されます。

期間を持つ工程を別の工程の基準にすると、**期間の終わり**が基準になります
（「受付期間の翌営業日に集計」が自然に書けます）。

| 項目 | 内容 |
|---|---|
| 工程名 | 自由入力。「封入封緘・点検」「進達書類の作成」など、係で使っている呼び方をそのまま |
| 基準 | 何を起点にするか。**起点の日**（審査会など）か、**別の工程** |
| 日数・単位・方向 | 「20」「営業日」「前」のように選ぶ |
| 担当／通知／休日補正／メモ | 各行の［v］で開く詳細に入っています |

**並べ替え**は行の左端をドラッグします。キーボードだけの場合は、左端にフォーカスして上下キーでも動かせます。
行と行の間にカーソルを置くと［ここに工程を追加］が現れ、途中に工程を差し込めます。

> 例）「決裁完了」＝ 基準「認定/不認定 決裁の起案」・方向「後」・日数「3」・単位「営業日」

「基準日の呼び方」も業務ごとに変えられます。審査会でも、締切日でも、受付開始でも、
その業務で実際に使っている言葉にしておくと、画面と通知の表示がそのまま通じる言葉になります。

### 起点の日（基準日）について

このツールは、**その業務で一番動かせない日を1つ決めて、そこから全工程を計算する**仕組みです。
この日を「起点の日」（シート上の名前は「基準日」）と呼びます。

**審査会のような会議日である必要はありません。**
締切日・発送日・受付開始日など、**すでに決まっている日**を選べば十分です。
呼び方も業務ごとに自由に変えられます。

**基本の使い方は「起点の日を足していくだけ」です。** 編集画面の［起点の日］に
日付を入れると、そこから全工程が計算されます。周期を意識する必要はありません。

毎月第2水曜のように**決まった周期がある業務だけ**、［決まった周期があるなら自動で並べる］を
開いて設定すると、以後の起点の日が自動で並びます。設定していても、臨時開催のような日を
1件だけ足すことができます。

### 特定の回だけを扱いたいとき

［起点の日］には、**この先に予定されている回がすべて**並びます（先読み月数のぶん）。
「9月分だけ組みたい」というときは、**不要な日の［×］を押して外します**。

自動で並べる設定が入っている業務では、外した日は消えずに「中止」として残ります。
これは意図的な作りです。単に行を消すと、翌日の自動更新でルールから作り直されて
復活してしまうためです。外した日は取り消し線付きで表示され、［↩］で戻せます。

表示する範囲そのものを狭めたい場合は、［設定］シートの `先読み月数` を小さくします。

シートに直接書く場合の記法は次のとおりです。

| 書き方 | 意味 |
|---|---|
| `毎月第2水` | 毎月第2水曜日 |
| `毎月最終金` | 毎月最終金曜日 |
| `毎月15日` | 毎月15日 |
| `毎月末日` | 毎月の末日 |
| `2ヶ月毎第2水 起点2026-04` | 隔月（2026年4月を起点に位相を合わせる） |
| `毎年9月1日` | 毎年9月1日 |
| `手動`（既定） | 自動で並べず、日付を手で登録する |

計算結果が休日になったときの寄せ方は「基準日休日補正」で指定します。

### 休日の調整

祝日は自動取得されますが、**団体独自の閉庁日や振替出勤**は［休日マスタ］シートに直接足してください。

| 種別 | 意味 |
|---|---|
| `閉庁` | 休みとして扱う（手入力分は自動同期で消えません） |
| `振替出勤` | 休日だが出勤する日。祝日指定より優先されます |

### 人に渡すとき

メニュー →［テンプレートの受け渡し］→［書き出す（JSON）］でコピーし、
渡した先のシートで［読み込む（JSON）］に貼り付けます。個人情報も進捗も含まれません。

## カレンダー連携を有効にする（任意）

既定ではカレンダー権限を要求しない構成です。使う場合のみ：

1. `appsscript.json` の `oauthScopes` に次を追加
   ```json
   "https://www.googleapis.com/auth/calendar"
   ```
2. ［設定］シートの `カレンダー同期` を `ON` にする（`カレンダーID` は空ならメインカレンダー）
3. 一度メニューから［工程表を再生成］を実行し、権限を承認する

以後、毎晩の自動更新でカレンダーへ終日予定として同期されます。

## 開発

コアロジック（営業日計算・基準日展開・工程算出・通知の振り分け）は
GAS の API に依存しない純粋関数として切り出してあり、Node で検証できます。

```bash
npm test          # コアロジックの検証（49件）
```

2026年の実際の祝日を使って、ゴールデンウィーク・年末年始・9月の3連休をまたぐ計算を検証しています。

画面の見た目は、Apps Script にデプロイしなくてもモックデータで確認できます。

```bash
npm run preview        # tests/preview/out/index.html を書き出す（ブラウザで開く）
npm run preview:shot   # 各ビュー・各テーマを撮影し、JSエラーの有無も報告する（要 playwright）
```

|---|---|

| `01_core_date.gs` | 日付ユーティリティ・営業日計算 |
